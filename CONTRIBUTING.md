# How to contribute

Thanks for wanting to improve **JS Interview Lab by DevByMike**. This is a community resource, and every bit of help counts.

## Ways to contribute

- Fix code bugs or typos.
- Improve an explanation to make it clearer.
- Add a new interview question.
- Add a new code challenge or an output question.
- Translate or clarify examples.

## Before you start

1. Fork the repository.
2. Create a branch with a descriptive name:
   ```bash
   git checkout -b add-closures-question
   ```
3. Make your changes.
4. Make sure the example code is valid by running it with Node.js:
   ```bash
   node path/to/file.js
   ```
5. Open a Pull Request explaining what you added or changed.

## Content style

To keep the repo consistent, follow these rules.

### Theory questions (`.md`)

Every question file should follow this structure:

```markdown
# Topic title

## Interview question
## Short answer
## Simple explanation
## Code example
## Common mistake
## How to answer it in an interview
## Quick challenge
```

### Code challenges (`.js`)

- Include the problem statement at the top in comments.
- Explain the input and the expected output.
- Use `console.log` to show examples.
- Comment on the *why* of the solution, not just the *what*.

### General rules

- Everything in **clear, direct English**.
- No excessive emojis.
- No `TODO`s or empty placeholders.
- Code that is **runnable** and correct.
- Written so a **junior** can understand it.

## Code of conduct

Be respectful. This is a space for learning. "Basic" questions are welcome: someone else has them too.
